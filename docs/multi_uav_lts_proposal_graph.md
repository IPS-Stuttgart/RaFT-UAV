# Multi-UAV LTS proposal graph experiment

This experiment tests whether the remaining Multi-UAV LTS gap is primarily an
association problem rather than a detector-recall problem. It operates on a
low-threshold proposal bank and builds complete trajectories offline.

The implementation is deliberately a falsifiable baseline, not a claim of
leaderboard improvement. The raw seeded YOLOv12-BoT-SORT output remains the
control in every guarded comparison.

## Hypotheses

The experiment separates four hypotheses:

1. **Persistent late births matter.** Unseeded proposal paths are emitted only
   after satisfying minimum hit, span, and mean-confidence requirements. A
   one-frame proposal cannot create an output identity.
2. **Delayed global linking repairs association gaps.** Strict reciprocal
   consecutive-frame links first create short anchor tracklets. A second
   offline assignment links non-overlapping tracklets using predicted motion,
   scale, overlap, velocity, confidence, and gap cost.
3. **Border-aware survival helps partial out-of-view sequences.** When source
   image dimensions are supplied, long links whose endpoints both lie near a
   frame boundary receive a controlled motion-cost discount.
4. **Any gain must survive raw-controlled evaluation.** The experiment includes
   no-global-link, no-border-discount, and strict-birth ablations. The existing
   guarded tournament rejects incomplete, statistically inconclusive, or
   scenario-regressing candidates.

## Tracker behavior

For each sequence, the tracker:

1. filters proposals below the configured confidence threshold;
2. removes near-identical same-frame proposals;
3. creates short tracklets only from reciprocal, sufficiently unambiguous
   consecutive-frame assignments;
4. maps frame-one tracklets to the supplied benchmark identities and inserts an
   exact seed-only tracklet when no proposal overlaps a seed;
5. solves an optional global one-predecessor/one-successor assignment over all
   tracklets;
6. preserves seeded path IDs;
7. confirms persistent unseeded paths as late births with deterministic new
   IDs; and
8. drops short or weak unseeded paths.

The path graph is acyclic because links always move forward in frame time. It
cannot merge two frame-one identities into one trajectory. Candidate links are
constructed only inside the configured temporal horizon and solved by connected
components, avoiding one sequence-wide dense assignment matrix.

## Focused synthetic tests

The regression suite covers:

- confirmation of a persistent late birth;
- rejection of a one-frame false birth;
- global bridging across missing detections;
- identity preservation for two crossing trajectories when future motion
  resolves the ambiguity;
- border-aware recovery after a long boundary gap;
- the no-global-link ablation;
- near-duplicate proposal suppression;
- directory and root-level ZIP proposal inputs;
- zero-overlap seed protection;
- preservation of unmatched exact seed rows;
- proposal-confidence and parameter-domain validation; and
- destructive output/input alias rejection.

Run the focused suite with:

```bash
PYTHONPATH=src RAFT_UAV_SKIP_RUNTIME_HOOKS=1 \
python -m pytest -q tests/test_multi_uav_lts_proposal_graph_tracker.py
```

## Run one candidate

```bash
PYTHONPATH=src RAFT_UAV_SKIP_RUNTIME_HOOKS=1 \
python -m raft_uav.multi_uav_lts.proposal_graph_tracker \
  /path/to/proposals \
  --first-frame-label-dir \
    /mnt/lexar4tb/multi_uav_lts/extracted/TrainLabels_FirstFrameOnly \
  --output-dir \
    /mnt/lexar4tb/multi_uav_lts/outputs/proposal_graph/predictions \
  --output-json \
    /mnt/lexar4tb/multi_uav_lts/outputs/proposal_graph/summary.json \
  --image-width 1920 \
  --image-height 1080
```

The proposal input may be a directory or ZIP containing root-level sequence
`.txt` files in the standard nine-column LTS format. Proposal object IDs are
interpreted as frame-local identifiers; output object IDs are reconstructed by
the graph.

The proposal bank is intentionally a separate input. It can be generated by the
low-threshold proposal exporter or supplied by another detector, but no
truth-derived oracle assignment may be used as tracker input.

## Data-backed workflow

The manually dispatched workflow is:

```text
Multi-UAV LTS proposal graph experiment
```

It runs four complete training candidates:

- `graph_default`;
- `graph_no_global`;
- `graph_no_border`; and
- `graph_strict_birth`.

Each candidate and the raw control are scored with the repository's
organizer-compatible evaluator. The guarded tournament then applies complete
coverage, paired bootstrap, MOTA/IDF1 floors, and worst-scenario HOTA guards.
A raw fallback is a valid negative result.

Pull requests run the focused synthetic suite and Ruff checks on a
GitHub-hosted runner. Manual runs can use `probe_only=true` to verify the
self-hosted runner, the 102 truth and seed files, proposal availability, and raw
control availability without running the tracker.

## Interpreting outcomes

- `graph_default > graph_no_global` supports delayed tracklet association.
- `graph_default > graph_no_border`, concentrated in BB2P or boundary-heavy
  sequences, supports border-aware survival.
- `graph_default > graph_strict_birth` with improved DetA supports controlled
  late births.
- Similar scores for all graph variants and a high identity-oracle score suggest
  that the remaining gap needs appearance features or higher-order trajectory
  optimization rather than parameter tuning.
- A raw tournament selection means the tested graph assumptions did not clear
  the evidence gates and should not be used for a test submission.

Store the proposal source, exact parameters, summary JSON, sequence metrics,
tournament evidence, git commit, and prediction digests with every result.
